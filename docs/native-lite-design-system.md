# Snow UI 设计系统

Snow UI 是 Snow Shot Native Lite 的桌面设计语言。目标是复用现代 Agent 工作台、IDE 和生产力工具的克制感，同时避免 WebView、Chromium 和重型前端运行时。

## 设计定位

关键词：

- Agentic productivity workspace
- Neo-utilitarian desktop UI
- Warm neutral palette
- Compact desktop density
- Subtle separators
- Minimal visual noise

它不是卡片堆叠式 SaaS 后台，也不是移动端大圆角界面。整个窗口应被视为一张连续工作台，层级主要依赖背景色差、1 px 分割线、选中态和留白，而不是阴影、渐变或玻璃效果。

## 平台范围

- 主平台：Windows 11 amd64。
- 第二适配平台：macOS arm64。
- 暂不为 Linux、Windows arm64 或 macOS x86_64 制定视觉与交互适配要求。

## 单一事实来源

- 机器可读 Token：`design/snow-ui.tokens.json`
- Slint Token：`apps/snowshot-native/ui/theme/snow-theme.slint`
- Slint 基础组件：`apps/snowshot-native/ui/components/`
- Slint 页面组合：`apps/snowshot-native/ui/pages/`
- 设置页骨架：`apps/snowshot-native/ui/app-window.slint`

修改颜色、间距、圆角、字体尺寸和控件高度时，应先修改 Token，再同步 Slint。禁止在具体页面中散落新的硬编码颜色。

## Slint 分层

- `theme/` 只维护颜色、排版、间距和尺寸 Token，不包含业务状态。
- `components/` 只维护可复用的无业务控件，以 property 和 callback 作为接口。
- `pages/` 负责页面信息架构、组件组合和业务 callback 转发，不直接实现系统能力。
- `app-window.slint` 只维护窗口属性、页面挂载和 Rust callback 边界。
- Rust service 只能绑定窗口或页面暴露的 callback，不得反向侵入主题与基础组件。

## 核心原则

1. **连续工作区**：优先使用分栏、分组和分割线，不为每一项包一张卡片。
2. **低色度暖灰**：避免纯白与纯黑直接对撞，降低长时间使用的视觉疲劳。
3. **紧凑但不拥挤**：使用 4 px 基础网格，导航行约 34 px，普通控件约 32 px。
4. **低噪声操作**：次要按钮、更多菜单和批量操作只在悬停、选中或聚焦时出现。
5. **小圆角**：普通控件 7 px，输入框和浮层 10 px，不使用 20 px 以上的气泡式圆角。
6. **少阴影**：默认不用阴影；浮层确有脱离背景的需要时才使用极轻阴影。
7. **克制强调色**：绿色强调色仅用于焦点、主操作、进度和当前状态。
8. **桌面优先**：保留右键菜单、键盘焦点、快捷键、可调整面板和高信息密度。

## 尺寸体系

- 间距：`4 / 8 / 12 / 16 / 24 / 32 px`
- 圆角：`4 / 7 / 10 / 14 px`
- 普通正文：`13 px`
- 导航和标签：`14 px`
- 分组标题：`18 px`
- 导航行：`34 px`
- 按钮与输入框：`32 px`
- 工具栏：`42 px`
- 顶栏：`44 px`
- 设置侧栏：`248 px`
- 检查器建议宽度：`360 px`

## 字体

默认使用系统 UI 字体，不内嵌字体文件：

- Windows：Segoe UI / Microsoft YaHei UI
- macOS：SF Pro

正文通常使用 400，标签和控件使用 500，当前页面和分组标题使用 600。避免大面积粗体。

## 组件规范

### Sidebar / Navigation

- 背景使用 `sidebar`。
- 每行 34 px，左右内边距 12 px。
- 未选中项不显示边框。
- 悬停使用 `surfaceHover`，选中使用 `surfaceSelected`。
- 次要元数据放在右侧，使用 12 px 和 `textMuted`。
- `...` 等次要操作默认隐藏，悬停后出现。

### Topbar

- 高度 44 px。
- 与工作区之间只使用 1 px 分割线。
- 标题 15 px、600 字重。
- 图标按钮 32×32 px，无永久底框。

### Buttons

- 高度 32 px，最小宽度 76 px，圆角 7 px。
- 次要按钮使用白色表面和 1 px 边框。
- 主按钮使用强调色；每个视图通常只保留一个主按钮。
- 图标按钮不应一直显示背景，仅在悬停、按下或选中时出现表面色。

### Settings rows

- 使用连续列表和分割线，而不是每项独立卡片。
- 标题 14 px，描述 12 px。
- 操作位于右侧，整行最小高度 54–58 px。
- 设置页左右留白 24 px。

### Capture toolbar

截图浮动工具栏应比设置页更紧凑：

```text
[矩形] [椭圆] [箭头] [画笔] [文字] [马赛克] | [OCR] | [复制] [保存]
```

- 高度 42 px。
- 图标按钮 32 px。
- 只给当前工具显示选中背景。
- 复制和保存放在最右侧；保存可作为唯一主操作。
- 不使用文字和图标同时堆叠，除非是首次使用引导。

### OCR 页面

采用设置工作区布局：

- 仅显示现有本地 OCR，不提供 Provider、PaddleOCR-VL 或远程服务入口。
- 中间显示 ONNX 模型状态、模型占用、最后使用时间和现有配置。
- 模型目录、自定义模型选择、热启动和写入内存选项沿用现有设置。
- 未安装、加载中、已就绪、错误等状态使用文字和小图标表达，不使用大面积彩色卡片。

## 页面结构

### 设置窗口

```text
┌──────────────┬────────────────────────────────┐
│ Snow Shot    │ 常规                           │
│              ├────────────────────────────────┤
│ 常用         │ 启动与行为                     │
│  截图        │ ────────────────────────────── │
│  贴图        │ 开机启动                 [启用] │
│  历史记录    │ ────────────────────────────── │
│              │ 关闭窗口时         [退出到托盘] │
│ 设置         │                                │
│  常规        │ OCR                            │
│  快捷键      │ ────────────────────────────── │
│  标注        │ 轻量本地 OCR             [配置] │
│  OCR         │ ────────────────────────────── │
│  保存        │ PP-OCRv4 ONNX           [就绪] │
└──────────────┴────────────────────────────────┘
```

### 历史记录

使用三栏结构，但右侧检查器可折叠：

- 左：日期和会话分组。
- 中：截图网格或当前截图预览。
- 右：尺寸、文件位置、OCR 文本、复制与导出。

### 贴图

贴图窗口本身应尽量无 UI，只保留右上角关闭按钮：

- 鼠标不在关闭按钮上时降低按钮透明度，悬停时恢复完整不透明度。
- 不使用右键关闭，不在右键时显示额外工具条。
- 四角保留不可见命中区和缩放光标，不绘制缩放方块；拖拽时保持截图比例，鼠标位于贴图上并按住 Ctrl 时，滚轮可围绕指针缩放。
- 等比缩放使用光标位移到对角线方向的连续投影，不在横向/纵向控制之间硬切换。
- 右侧和下侧使用固定 6px 的轻量高斯模糊阴影，阴影与贴图作为同一合成事务更新。
- Windows 缩放期间不得重新上传或重新绘制截图位图，只允许更新 DirectComposition 变换和窗口命中区域。

## 动效

- 悬停：约 80 ms。
- 普通状态切换：约 140 ms。
- 面板展开和宽度变化：约 180 ms。
- 禁止弹性过冲、夸张缩放和长时间渐变。
- 截图时优先保证响应速度；任何动画都不得阻塞选区反馈。

## 无障碍与输入

- 所有交互元素必须具备键盘焦点和可见焦点环。
- 文字与背景保持足够对比度。
- 图标按钮应提供可访问名称和工具提示。
- 支持 100%–250% 缩放与多显示器混合 DPI。
- 不以颜色作为唯一状态表达方式。

## 禁止项

- 大面积渐变背景。
- 毛玻璃作为主要层级手段。
- 每个设置项都套独立圆角卡片。
- 20 px 以上的常规圆角。
- 多层浓重阴影。
- 大字号营销式标题。
- 多个强调色按钮争夺注意力。
- 页面级硬编码颜色和任意间距。

## 迁移规则

当前 Tauri/React 版本仍作为行为参考，但 Native Lite 不复用其 Ant Design 视觉层。迁移每个页面时：

1. 先确认信息架构与功能范围。
2. 用 Snow UI Token 搭建原生布局。
3. 将 Rust Core 接入组件回调。
4. 验证键盘、DPI、主题和内存。
5. 删除对应 WebView 页面后，再移除旧依赖。

验收时，页面需同时满足视觉一致性、无 WebView 依赖和目标内存范围。
